Chromium Open Source Health - Review Feedback

This analysis is imperfect and is intended as a learning guide only.

How much review feedback do your Chromium changes draw, where does it come from, and how does that compare with other authors? Reviewers start fewer threads on a change as its author learns the code, so the feedback on your changes is one view of where you are still learning. Type your email address to see the reviewer threads on every change you landed since July 2023, set against authors with the same tenure, in the same organization, or with the same experience in each directory you changed.

It counts feedback, not quality. Reviewers, teams and kinds of work differ a lot, and some of the most valuable changes draw the most discussion. Use it to find patterns worth a look, not to rank anyone.

      How it's measured

      Changes are the merged, human-owned Chromium changes on main that landed from July 2023 to October 2026, leaving out mechanical ones (100 or more files, or mostly repeated lines), as on the Review Balance page. A reviewer thread is a comment thread on Gerrit started by someone other than the change's owner, bots left out. It is addressed when the owner's reply led to a change in the code, as judged by a regular expression for “Done”-style replies and by an AI model (Claude Haiku) for the rest (how).

      Adjusting for size compares each change with the 2023–24 average for changes in the same of ten size bands (by lines changed); adjusting for directory as well uses the average for that size in the same two-level directory, where there are 30 or more such changes. Peers are the authors who landed or more changes in the same dates; tenure counts from a person's first commit on main and is taken at the middle of their changes; an author's organization is the one most of their changes in the dates are attributed to. Comparing with the same experience in each directory divides everyone's feedback by what all authors drew at the same number of earlier commits in that directory.

      Addresses are matched as in the Review Balance page: chromium.org and google.com addresses with the same name are one person, and so is a Gerrit owner with the git author of the same changes. The data has one file per person, named by a one-way hash of their address, so this page can only find someone whose address you already know. Everything comes from public Gerrit and git data. Code and method: docs/review-feedback.md.
