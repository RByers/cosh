          How this is measured

          Commits are the first-parent history of Chromium's main branch from July 2017, when Chromium's code review moved to Gerrit and commits began to carry Reviewed-by footers. Only whole quarters are shown, so the page changes when a quarter completes.

          Lines reviewed come from git alone: a commit's added plus removed lines (a renamed file counts by the lines changed in it, a binary file as none), once for each person in its Reviewed-by footers other than its author. Commits by bots, reverts, large-scale changes and mechanical commits (100 or more files, or 10 or more that repeat the same edit) are left out, since nobody reads those line by line. A commit with two reviewers counts twice: the measure is review work, not code. Reviewed-by names those who approved; reviewers who only commented are not counted here.

          Review times come from Gerrit, for the same commits' changes. A reviewer is anyone but the change's owner, bots left out; an answer is a Code-Review vote or a comment before the change closed. For changes with no comments, only the votes standing when the change closed are known. The attention set exists from late 2020; its hours are counted from , from the change's creation to its close, overlapping turns once.

          Addresses are matched as in the Feedback Index: chromium.org and google.com addresses with the same name are one person. A reviewer's data is in a file named by their address in storage that can't be listed, so this page can only show someone whose address you already know. Everything comes from public Gerrit and git data. Code and method: docs/review-load.md.
