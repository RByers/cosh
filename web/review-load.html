          How this is measured

          Commits are the first-parent history of Chromium's main branch from July 2017, when Chromium's code review moved to Gerrit and commits began to carry Reviewed-by footers. Only whole quarters are shown, so the page changes when a quarter completes.

          Lines reviewed come from git alone: a commit's added plus removed lines (a renamed file counts by the lines changed in it, a binary file as none), once for each person in its Reviewed-by footers other than its author. Commits by bots, reverts, large-scale changes and mechanical commits (100 or more files, or 10 or more that repeat the same edit) are left out, since nobody reads those line by line. A commit with two reviewers counts twice: the measure is review work, not code.

          Reviewers here are approvers. Gerrit writes a Reviewed-by footer for each positive Code-Review vote standing on the patch set that lands, so a reviewer who was added to a change but never voted, or whose vote a later patch set cleared, isn't in it. In 2025, 99.8% of Reviewed-by names had such a vote (the rest voted under another address), while 16% of the reviewers added to changes weren't named, nearly all of them never having voted: another reviewer approved first. Reviewers who only commented aren't counted in lines reviewed.

            Review times come from Gerrit, for the same commits' changes. A reviewer is anyone but the change's owner, bots left out, whether or not they approved: being asked is load even when someone else answers first. An answer is a Code-Review vote or a comment before the change closed. For changes with no comments, only the votes standing when the change closed are known. The attention set exists from late 2020; its hours are counted from , from the change's creation to its close, overlapping turns once.

            Owners are read from the OWNERS files on main at the end of the last quarter shown: a file's owners are the people listed in its directory's OWNERS file and in those of the directories above (up to one that says set noparent), with file:// includes followed. Rules for single files (per-file) are not read, and a directory where anyone may approve (*) counts every reviewer as an owner. Someone counts as a committer from their first Code-Review vote in Gerrit, or from their first commit that landed with one reviewer; a commit by anyone else that has two or more reviewers is one that needed two approvals.

            Addresses are matched as in the Feedback Index, only on evidence: a Gerrit owner and the git author of the same changes, or a reviewer's address and the account that cast the vote. Sharing a name across chromium.org and google.com isn't enough. Someone with several addresses is named by the one they used most recently, so a person who changed theirs is called by their current one. A reviewer's data is in a file named by their address in storage that can't be listed, so this page can only show someone whose address you already know. Everything comes from public Gerrit and git data. Code and method: docs/review-load.md.
