Chromium Open Source Health

One way to judge the health and stability of an open source project is to ask whether each stakeholder's investment in it is proportionate to the value it gets out of it. When that value exchange is far out of balance, it can lead to a rupture in the project community. Quantifying the exchange is usually impossible, but Chromium makes an approximation possible. The value a browser gets from its engine is roughly proportional to that browser's usage. Today, the biggest cost of maintaining a large open source project is the human effort of directing how the codebase evolves and reviewing changes. AI coding agents are making code cheap to write, which makes deciding what should and shouldn't land in the project more valuable. Code review is therefore a reasonable proxy for an organization's investment.

This page approximates that value exchange by comparing each organization's share of Chromium-based browser usage with its share of Chromium code reviews.

Review by organization

Scale

What's counted. Code review on chromium/src CLs targeting main, grouped by the ISO week each CL closed (merged or abandoned; review that stops a CL from landing still counts). Only CLs owned by humans are included, so autorolls and other bot commits are left out. Reviews by bots and AI agents are dropped too, as are owners' comments on their own CLs.

Metrics. Review comments are published comments, inline or patchset-level, written before the CL closed. Comments that declare themselves AI-generated, and comments written after the CL landed, are counted separately (see the table below). A Code-Review vote with no comment, such as a bare +1, counts as one comment, so reviews that needed no changes still show up. Reviewed CLs counts the CLs where someone from the organization voted or commented. Review characters is the length of those comments with quoted (>) lines removed.

Organization. Each reviewer is assigned to an organization as of the date the CL closed, using the first rule that applies: (1) if the reviewer is listed in Chromium's own affiliations.json5, the affiliation in effect on that date is used. This lets an @chromium.org or personal address count for the person's employer, and follows people who change employers; (2) other @chromium.org accounts count as Google (google.com); (3) everyone else counts for their email domain, with Meta's old fb.com merged into meta.com. The chart shows the organizations with the most review; the rest, including gmail.com addresses, are combined as “Other”.

Chromium browser usage (Cloudflare Radar)

The ratio's denominator: each browser's share of Chromium-based browser usage, including Android WebView and in-app browsers. Human traffic, complete ISO weeks, iOS excluded.

WebViews and in-app browsers. Pages opened inside apps count as Chromium usage. Android System WebView (ChromeMobileWebview), the Chromium engine Google ships for apps, is credited to Google along with Chrome. The Facebook and Instagram in-app browsers are credited to Meta, and Microsoft 365's to Microsoft. Other in-app browsers (Snapchat, Pinterest and others) stay in the denominator but are credited to no organization.

iOS is excluded. Every iOS browser, Chrome included, must use Apple's WebKit engine, and in-app browsers there use WKWebView, so Chromium is barely used on iOS. Radar can't filter iOS out directly, so each day's iOS traffic is subtracted from the all-platform figures using Radar's iOS-only browser breakdown and iOS share of requests.

Brave is excluded. Brave sends Chrome's User-Agent string and names itself only in the Sec-CH-UA client hint. Radar reports it at about 0.002% of Chromium usage, roughly a thousand times below Brave's real size, so Brave's usage is unknown and is most likely counted as Chrome. brave.com therefore gets no usage share or value ratio. If Brave's real share was moved out of Chrome, Google's usage share would be a few points lower and its value ratio slightly higher.

Note on ChromeDerivative. Radar's bucket for Chromium-based browsers it can't name jumped from about 0.3% to about 10% of Chromium usage starting in 2026-W37 (on 9 September 2026). It came from every browser in proportion, Safari and Firefox included, not mostly from Chrome. It looks like Radar started labeling traffic it previously couldn't identify, possibly real Chromium-based browsers; Cloudflare hasn't explained it. The bucket stays in the denominator but is credited to no organization, so from W37 every organization's usage share is about 10% lower and its value ratio about 11% higher.
